## Observation

`sl-prim/src/shape.rs` `PathCurve::from_byte` matches the whole byte
(`0x20 => Circle`, `0x30 => Circle2`, `0x80 => Flexible`, else `Line`). The
reference switches on `getCurveType() & 0xf0` (`llvolume.cpp` ~1433, ~1493)
and has an `LL_PCODE_PATH_TEST` (0x40) case.

## Effect

A path byte with low bits set (e.g. 0x21) renders as a line instead of a
circle; 0x40 renders as a line instead of the five-point test path. Rare in
practice, silent when it happens.

## Fix

Mask with 0xf0 in `from_byte`, add the test path, and keep the raw byte where
round-tripping must stay lossless (`sl-object-asset`'s bridge — see
[[idiomatic-prim-flags-and-object-codes]]). Unit-test the masked decode.

## Fixed (2026-11-09)

- `PathCurve::from_byte` (`sl-prim/src/shape.rs`) decodes `byte & 0xf0` like
  `LLPath::generate`: `0x21` is a circle, and every uncovered nibble is a
  line. Flexi stays an exact `== 0x80`, as the reference tests it
  (`llvolume.cpp`, `llvovolume.cpp`), so `0x81` is a line.
- New `PathCurve::Test` (`0x40`), generated by `Builder::build_test`
  (`sl-prim/src/path.rs`), a port of the reference's five-frame
  `LL_PCODE_PATH_TEST` branch: it ignores cut, shear and split, turns about X
  by `pi * twist_end * t` and lerps the scale to the top size.
- The edit panel classifies a test path as Box. The reference's
  `MI_PATH_TEST_*` items sit past the eight entries its combo shows, and Box is
  its own fallback.
- `sl-object-asset`'s bridge already carried the curve bytes verbatim.
  `a_path_byte_with_low_bits_set_round_trips_verbatim` now pins it for `0x21`,
  `0x45` and `0x81`.
- Pinned by `path_curve_decodes_the_high_nibble_but_flexi_exactly` and
  `test_path_curls_five_frames_through_the_end_twist`.

Found along the way and filed as [[prim-shape-exact-curve-byte-checks]]: the
reference's split, uncut-box cap and LOD-bias checks compare the *whole* path
and profile bytes, and our checks compare decoded kinds.
